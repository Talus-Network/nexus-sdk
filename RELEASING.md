# Releases

One workspace version and one annotated tag identify each release.

| Output | Distribution |
| --- | --- |
| SDK, Toolkit | crates.io, SDK first |
| CLI | GitHub archives for Linux x86_64 and macOS Intel and ARM, plus Debian |
| Walrus, GCP KMS | Git tag |
| Homebrew, AUR | CLI artifacts from that tag |

## Prepare

1. Branch from current remote `main` and run `just release-prepare VERSION`.
1. Review the version changes and release notes. Record incompatible changes in the changelog.
1. Open a PR into `main`. Require normal CI and run the `Release` workflow on the PR branch to verify packages and all CLI targets without creating a release.
1. Merge after review. Create `release/vMAJOR.MINOR.x` at the merged commit, then create and push an annotated `vVERSION` tag at that commit.

The preparation command updates workspace versions, dependency requirements, the lockfile and current installation examples. Rust scaffolds inherit the CLI version. Historical release notes stay unchanged.

## Publish

1. Wait for the tag's `Release` workflow to finish. It creates a draft with CLI artifacts and SHA256 checksums after package and consumer checks pass.
1. Run `Publish crates.io packages` from `main` with the release tag. It checks out that tag, publishes SDK then Toolkit, and checks consumers against crates.io.
1. Check both docs.rs builds and compile a Rust Tool generated by the released CLI.
1. Publish the GitHub draft after those checks pass.
1. Update the Homebrew formula and AUR recipe from the published artifacts and checksums. Verify installation and `nexus --version`.

For example, publish packages with:

```sh
gh workflow run publish-crates.yml --ref main -f tag=v2.2.0
```

SDK and Toolkit are the only crates published to crates.io. Walrus uses the registry SDK. GCP KMS consumers take SDK and the adapter from the same Git tag.

## Recovery

Keep released tags and artifacts unchanged. For a partial crates.io publication, verify the existing crate matches the release commit before rerunning with `resume=true`. Fix published defects in a new version.

A release is complete when registry consumers, CLI installation, documentation, Homebrew and AUR agree on the version.
